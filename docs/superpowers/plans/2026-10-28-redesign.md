# Redesign Implementation Plan

> Executed inline (Native), the method the user chose for V2. Spec: `docs/superpowers/specs/2026-10-28-redesign-design.md`.

**Goal:** the "night study" redesign, with a real terminal, a full Settings page and prompt-bar controls.

**Global constraints**
- Nothing is committed unless the user asks.
- Never start Claude in tests.
- Don't touch V1.
- Colours, sizes and copy are exactly as in the spec.

### Task 1: Context numbers and per-chat model and effort (logic, TDD)
- In `src/main/claude.js`, `parseClaudeLine` sends `usage` events.
  - Test in `test-claude.mjs`: `parseClaudeLine usage`. An assistant line with `usage {input_tokens:10, cache_read_input_tokens:100, cache_creation_input_tokens:5, output_tokens:7}` gives `{type:'usage', used:122, window:1000000}`. A result with `modelUsage {m:{contextWindow:1000000}}` gives `{type:'usage', window:1000000}`.
- In `store.js`, chats gain `workerModel`, `workerEffort` and `context`. Add `chatSetting(id, key, value)` and `startFresh(id)`, which clears `managerSessionId`, every worker's `sessionId` and `context`.
  - Tests in `test-store.mjs`: `chat settings and start fresh`, and `old chats get no override` (falls back to the settings defaults).
- In `workers.js`, the model and effort come from `chat.workerModel ?? settings.workerModel` and the same for effort. A `usage` event updates that worker's context, and `pool.context()` returns `[{ name, used, window }]`.
  - Test in `test-workers.mjs`: `uses the chat's model and effort; keeps context numbers`.
- In `managerapi.js`, `usage` updates the Manager's context, and `api.context()` returns `{ used, window }`.
  - Test: `manager context numbers`.

### Task 2: Shell IPC (main)
- Add `src/main/shells.js`, with `resolveShells(): [{ id, label, file, args }]` (PowerShell, pwsh, cmd; only those installed) and `pickShell(id, list)`.
  - Test in `test-shells.mjs`: an unknown id falls back to the first entry.
- Add `pty:create`, `pty:write`, `pty:resize` and `pty:kill`, with `pty:data` and `pty:exit` events, in `main.js` and `preload.js`.
  - The cwd must pass `runGuard({ role:'worker', cwd }, trusted)`.
  - Output is batched per 16ms.
  - Everything is killed on quit.
  - Add `shells:list`.

### Task 3: Styles and layout
- Rewrite `styles.css` with the tokens, fonts (`@font-face` pointing at node_modules), panels, sidebar, chat, composer controls, popover, settings page, terminal, animations and the animation levels (`body[data-motion]`).
- Restructure `index.html`: the title bar view switch, `#sidebar` and `#main`, with the main panel holding `#chat`, `#terminal` and `#settings`.

### Task 4: Sidebar and Settings page
- Rebuild `sidebar.js`: the header row (New chat as plain text, an Add project icon, a Settings icon), with Add project calling `folder.pick({ trust: true })`. Main sets the dialog `title` and `buttonLabel` to "Trust this folder".
- Rewrite `settings.js` as a page: `SECTIONS` data drives the section list and content. Esc or Back returns to the chat.
- The `confirmDeletes` setting gates the delete confirmations.

### Task 5: Composer controls and context popover
- In `chatview.js`, add the ring (an SVG arc showing the percentage), the popover with bars and Start fresh, the model menu and the effort slider (`input[type=range]` with 5 steps and a label).
- `ctx` adds `contextOf(chatId)`, `chatSetting(...)` and `startFresh(chatId)`.

### Task 6: Terminal view (rebuilt)
- Delete `terminalsview.js`. Add `terminal.js`: xterm with the fit addon, tabs per project, "+", close, `Ctrl+\`` to toggle and `Ctrl+Shift+\`` for a new tab, and resizing to fit.
- Wire it into `app.js` in place of the old view.

### Task 7: Look tests and final review
- Look tests: welcome, a chat with live lines and a summary, the context popover, settings sections, and a terminal with a real PowerShell tab running `echo hello`.
- Then a fresh whole-change review, and fix the Important findings with tests.
